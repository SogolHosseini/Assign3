Test Case 1
TC-01 Marketplace Correctly Excludes the Signed-In User's Own Listings
Description Verifies that the Marketplace page (marketplace.html) only displays items listed by other users and never shows items where the currently signed-in user is the seller. This tests the core filtering requirement of the application.
Preconditions
  1. The application is running via Live Server (http://127.0.0.1:5500).
  2. Firebase Firestore contains at least 8 items spread across at least 3 user accounts.
  3. At least 2 items in Firestore have sellerUID matching the test user's UID (user1@test.com).
  4. At least 3 items belong to other users (user2@test.com or user3@test.com).
  5. The user is currently signed out (login page is visible).
Test Steps
  1. Open the application at http://127.0.0.1:5500/login.html.
  2. Enter email: user1@test.com and password: Test1234!.
  3. Click the Sign In button.
  4. Confirm the Welcome page (index.html) loads and displays "Signed in as user1@test.com".
  5. Click Browse Marketplace from the navigation cards.
  6. Wait for all items to finish loading from Firestore (spinner disappears).
  7. Inspect every visible item card on the Marketplace page and note the seller email displayed on each card.
  8. Verify that none of the item cards show user1@test.com as the seller.
  9. Count the total number of items displayed and compare with the total items in Firestore minus the items owned by user1.
Expected Result The Marketplace page loads and displays items from other users only (user2@test.com and user3@test.com). No item card shows user1@test.com as the seller. The item count shown in the top filter bar matches the number of Firestore items that do not belong to user1.
Actual Result The Marketplace page loaded and displayed items belonging to user2@test.com and user3@test.com only. All item cards were verified and none showed user1@test.com as the seller. The item count correctly reflected the filtered results.
Pass / Fail PASS
Test Case 2
TC-02 Shortlist Item Persists Across Sessions and Cannot Be Duplicated
Description Verifies that when a user shortlists an item from the Marketplace, the shortlist entry is saved to Firestore and persists after signing out and signing back in. Also verifies that the "Add to Shortlist" button becomes disabled and changes to "Shortlisted" after the item is saved, preventing duplicate shortlist entries.
Preconditions
  1. The application is running via Live Server.
  2. Firestore contains items from at least two different user accounts.
  3. user2@test.com has no shortlisted items in Firestore at the start of this test (the shortlists collection contains no documents with userId matching user2's UID).
  4. The user is currently signed out.
Test Steps
  1. Sign in as user2@test.com / Test1234!.
  2. Navigate to the Marketplace page.
  3. Locate any item card and click its + Add to Shortlist button. Note the item's name.
  4. Observe that the button immediately changes text to ✓ Shortlisted, turns green, and becomes disabled.
  5. Click the + Add to Shortlist button on the same item again to confirm it cannot be clicked (button should be disabled).
  6. Click the Sign Out button on the Marketplace page.
  7. Confirm redirection to login.html.
  8. Sign back in as user2@test.com / Test1234!.
  9. Navigate to My Shortlist from the Welcome page.
  10. Verify the previously shortlisted item appears in the list with the correct name.
  11. Navigate back to Marketplace — confirm the button for that item still shows ✓ Shortlisted and is disabled.
Expected Result After clicking "Add to Shortlist", the button immediately becomes disabled and shows "✓ Shortlisted" in green. After signing out and back in, the item still appears in My Shortlist, confirming Firestore persistence. On the Marketplace, the same item's button remains in the "Shortlisted" state, confirming that the check against Firestore on page load prevents duplicate shortlisting.
Actual Result The shortlist button changed state immediately after clicking. After signing out and signing back in, the item appeared in My Shortlist. On revisiting the Marketplace, the button for that item correctly displayed "✓ Shortlisted" in green and was disabled, confirming both persistence and duplicate prevention.
Pass / Fail PASS
